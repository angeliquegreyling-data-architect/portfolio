02 // DATA EXTRACTION & REPOSITORY GOVERNANCE

Automated Extraction & Repository Management

1. Automated Inbound Extraction

The pipeline replaces manual spreadsheet extraction procedures with an automated scripting proxy. A dedicated script monitors the inbound data mailbox, identifies incoming operational report attachments, and programmatically captures the associated spreadsheet files for downstream processing.

2. Raw Snapshot Archival

Extracted report attachments are committed directly into a structured archival folder hierarchy within Google Drive. The raw snapshot repository preserves the original incoming reporting artifacts independently of subsequent transformation operations, providing a historical reference point for reconciliation and operational audit requirements.

3. Transaction Isolation & Duplicate Prevention

Following successful attachment extraction and archival, the processed message container is cleared. This isolates completed ingestion transactions from subsequent mailbox monitoring cycles and prevents previously processed messages from repeatedly entering the extraction sequence, reducing the risk of multi-pass file duplication.

03 // AUTOMATED TRANSFORMATION ENGINEERING

TypeScript Data Normalization Loop (Office Scripts)

1. Automated Processing Trigger

Upon detection of a new repository file drop, the automated workflow invokes a custom TypeScript execution block through Office Scripts. The transformation engine accesses the target workbook, identifies the active worksheet and retrieves its used data range before initiating structural normalization operations.

2. Structural Grid Normalization

The script identifies the populated worksheet boundaries through getUsedRange() and retrieves the active row and column dimensions. It then executes an unmerge() operation across the used range, removing nested layout block headers and restoring a consistent tabular structure for downstream transformation.

3. Algorithmic Header Sanitization

A column traversal loop reads the first-row header value for each populated column. Non-empty header values are normalized through whitespace trimming, lowercase conversion and whitespace replacement using trim().toLowerCase().replace(/\s+/g, '_'). This establishes consistent field naming conventions and reduces structural inconsistency caused by variations in incoming spreadsheet headers.

4. Canonical Table Object Generation

Following header normalization, the sanitized worksheet range is converted into a structured Excel Table Object through workbook.addTable(). The resulting table is assigned the canonical identifier Canonical_Operational_Ledger, establishing a standardized tabular contract for subsequent automation and analytical consumption.

5. TypeScript Execution Reference

The following Office Script implements the worksheet access, structural unmerging, header sanitization and canonical table generation sequence.

function main(workbook: ExcelScript.Workbook) {
  // Access target data sheet layer
  let targetSheet = workbook.getActiveWorksheet();
  let usedRange = targetSheet.getUsedRange();

  if (usedRange) {
    let rowCount = usedRange.getRowCount();
    let colCount = usedRange.getColumnCount();

    // Unmerge nested layout block headers
    usedRange.unmerge();

    // Algorithmic downward text fill
    for (let col = 0; col < colCount; col++) {
      let firstHeaderValue =
        targetSheet.getCell(0, col).getValue() as string;

      // Normalize column header names
      if (firstHeaderValue) {
        let sanitizedHeader = firstHeaderValue
          .trim()
          .toLowerCase()
          .replace(/\s+/g, '_');

        targetSheet.getCell(0, col).setValue(sanitizedHeader);
      }
    }

    // Generate canonical structured table
    let activeTable = workbook.addTable(
      usedRange.getAddress(),
      true
    );

    activeTable.setName("Canonical_Operational_Ledger");
  }
}

04 // ANALYTICAL MODELING & DELIVERY

Power BI Analytical Modeling Layer

1. Structured Data Publication

The normalized operational table is published directly into a secure corporate SharePoint workspace. This establishes a centralized processed ledger that separates raw snapshot archival from the standardized dataset consumed by downstream analytical systems.

2. Incremental Refresh Architecture

Power BI connects to the published workspace records and executes scheduled incremental refresh operations against the structured dataset. By consuming pre-normalized table structures, the analytical layer avoids repeatedly processing complex spreadsheet layout modifications during downstream data model refresh operations.

3. Analytical Processing Optimization

Complex structural data modifications are handled upstream within the TypeScript normalization loop, allowing the Power BI semantic model to remain comparatively lightweight and focused on analytical execution. This separates ingestion and transformation responsibilities from business intelligence calculations, preserving analytical capacity for complex DAX measures, management reporting and executive dashboard delivery.
