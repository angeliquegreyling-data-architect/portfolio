SPECIFICATION 01 // EXTRACTION

Automated Extraction & Repository Management

The pipeline replaces manual extraction loops with an automated scripting proxy. A dedicated script monitors the inbound data inbox, captures incoming spreadsheet attachments, commits the raw snapshot rows directly into an archival folder structure, and clears the processed message container to isolate the transaction and prevent multi-pass file duplication.

Architectural Objective

Raw snapshots are retained separately from downstream processed records, creating a clear boundary between source data preservation and analytical data transformation.

SPECIFICATION 02 // NORMALIZATION

TypeScript Data Normalization Loop

Upon repository file drop detection, an automated workflow calls a custom TypeScript Office Script to standardize unstructured grid data into clean tables before downstream analytics systems query the row models.

TYPESCRIPT OFFICE SCRIPT // NORMALIZATION ENGINE 
function main(workbook: ExcelScript.Workbook) {

    // Access target data sheet layer
    let targetSheet = workbook.getActiveWorksheet();
    let usedRange = targetSheet.getUsedRange();

    if (usedRange) {

        let rowCount = usedRange.getRowCount();
        let colCount = usedRange.getColumnCount();

        // Unmerge nested layout block headers
        // to clean the table space
        usedRange.unmerge();

        // Algorithmic column normalization
        for (let col = 0; col < colCount; col++) {

            let firstHeaderValue =
                targetSheet
                    .getCell(0, col)
                    .getValue() as string;

            // Clean and normalize column header names
            if (firstHeaderValue) {

                let sanitizedHeader =
                    firstHeaderValue
                        .trim()
                        .toLowerCase()
                        .replace(/\s+/g, '_');

                targetSheet
                    .getCell(0, col)
                    .setValue(sanitizedHeader);
            }
        }

        // Force sanitized data into a
        // structured Table Object mapping contract
        let activeTable =
            workbook.addTable(
                usedRange.getAddress(),
                true
            );

        activeTable.setName(
            "Canonical_Operational_Ledger"
        );
    }
}
Canonical Data Contract

The normalization process converts a variable, presentation-oriented spreadsheet layout into the structured Canonical_Operational_Ledger table contract, providing a consistent boundary for downstream processing and analytics.

SPECIFICATION 03 // ANALYTICS

Power BI Analytical Modeling Layer

The structural table is published directly into a secure corporate workspace where Power BI executes scheduled refreshes against the processed records. Complex spreadsheet modifications are handled upstream within the automation layer, allowing the analytical model to remain focused on semantic calculations and executive reporting.

STEP 01

Structured Ledger

Normalized snapshot records are committed to the processed repository.

STEP 02

Scheduled Refresh

Power BI retrieves structured records through automated workspace refresh processes.

STEP 03

Semantic Modeling

The analytical model remains lightweight and focused on business logic and DAX calculations.

STEP 04

Executive Analytics

Final dashboards deliver structured operational insights for management review.

Processing Boundary Principle

Complex structural transformations are completed before data reaches the analytics layer. This separation keeps reporting models faster, reduces transformation overhead, and allows the semantic layer to concentrate on analytical calculations rather than source-file remediation.
